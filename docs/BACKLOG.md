- 2026-11-10: 기존 경유지를 유지하면서 주유소를 첫 번째로 삽입하는 기능을 재검토한다.
  - 환경: Pleos Connect v2.1.0 / Navigation 3.3.2-rc5-hotfix.3 / NaviHelper 3.0.5.
  - 재현: 기존 세종주유소 경유 → 판교운중주유소 목적지 상태에서 17:07:20 앱이 퍼스트주유소를
    `addWaypoint(FIRST)`로 요청했다. 17:07:26·17:07:36 조회 결과는 세종주유소 → 퍼스트주유소였으며,
    기대한 퍼스트주유소 → 세종주유소 순서와 달랐다. 해당 환경에서 FIRST 요청이 기존 경유지를 두 번째로 이동시킨다고 보장할 수 없다.
  - 영향: SDK 요청은 반영됐지만 앱의 ID·개수·순서 검증을 통과하지 못해 성공으로 확정되지 않는다.
    결과 불확실 상태가 남으면 중복 변경 방지를 위해 후속 제출도 차단된다. 단순 성공 조건 완화는 사용자가 요청한 순서를 보장하지 못한다.
  - 대안과 제약: `requestRouteWithWaypoints`로 주유소 → 기존 경유지 → 기존 목적지를 명시할 수 있지만,
    시스템 경유지 조회가 좌표 (0,0), poiSubId=null을 반환한다. 현재 조회 결과만으로 임의의 기존 경유지를 유효한 요청 정보로
    재구성할 수 없다. POI ID만으로 정확한 진입 위치가 복원되는지, null sub-ID를 대체할 수 있는지도 확인되지 않았다.
    조회 좌표 (0,0)를 성공 확인에서 제외하는 정책은 경로 요청에 (0,0)을 사용해도 된다는 의미가 아니다.
  - 현재 정책: 목적지가 있고 기존 경유지가 0개일 때만 경유 추가를 허용한다. 1개·2개 모두 경유 추가를 비활성화하고,
    저장소에서도 SDK 호출 전에 WAYPOINT_UNAVAILABLE로 거부한다. 기존 목적지·경유지를 대체하는 목적지 설정은 확인 팝업과 함께 유지한다.
  - 재개 조건: SDK의 순서 지정/변경 계약 확인, 기존 POI의 유효 좌표·sub-ID 재확보 또는 ID 기반 복원 지원 확인이 필요하다.
    복원 가능한 정차 환경에서 새 주유소 첫 번째·기존 경유지 두 번째·목적지 유지 및 실패 시 부분 반영/복구를 검증한 뒤 기능을 다시 연다.
    원경로를 임의 초기화하거나 null sub-ID를 0으로 변환해 해결했다고 간주하지 않는다.
