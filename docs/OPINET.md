# 오피넷 반경 검색

`core:data`의 Retrofit 클라이언트가 `aroundAll.do`를 JSON·거리순으로 호출한다. 키는 `local.properties`의
`OPINET_API_KEY`에서 app BuildConfig/Koin으로 공급한다. HTTP 로그를 사용하지 않으며 HTTP/네트워크 오류는 URL을 포함한 원본 예외 없이
분류한다. APK에 포함된 키는 비밀로 보장하지 않는다.

HTTP·네트워크·타임아웃·API 오류 및 잘못된 응답은 최초 요청 후 0.5초·1초 간격으로 최대 2회 재시도한다 (총 최대 3회).
빈 정상 목록은 성공이며 재시도하지 않는다. 취소·키 누락·입력 검증 실패도 재시도하지 않는다. 각 시도는 연결 10초·전체 30초 제한이며,
모두 실패하면 기존 오류 분류로 반환한다. Pleos Trip은 이 HTTP 재시도의 대상이 아니다.

인증키 쿼리 이름은 **`code`**다. 2026.10판 `Opinet_API_Free.pdf` 4쪽·12쪽을 기준으로 한다. 웹 상세 페이지의 `certkey`와 달라 실제
같은 키로 대조했으며 `certkey`는 HTTP 200/빈 배열, `code`는 평균가격 5건·공식 예시 좌표 반경 3km에서 34건을 반환했다. 빈 배열이나 HTTP
200만으로 인증 성공을 판정할 수 없다. 인증키와 전체 요청 URL을 기록하지 않는다.

검색 반경은 3km로 고정하며 과거에 저장된 다른 반경은 무시한다. 유종은 휘발유 B027 (기본)·고급휘발유 B034·경유 D047이며 선택 즉시 DataStore에 저장한다.
검색 시작 시 조건을
고정하고 결과 재검색도 같은 조건을 사용한다. 새 홈 검색은 최신 설정을 사용한다. 상세 API·가격 캐시는 추가하지 않았다.
응답의 거리순(`sort=2`)을 유지하고 가격·식별정보·좌표가 유효한 가까운 최대 15곳만 비교·순차 Trip 대상으로 사용한다.
15곳 미만이면 모두 사용하며, Trip 실패 시 16번째 이후 후보로 보충하지 않는다. 비교 기준 최고가도 이 중 경로 확보 후보에서 구한다.

검색·재검색은 화면의 이전 세션 출발 위치와 비교하지 않고, 시작 시 조회한 최신 위치로 오피넷에 요청한다.
API 응답·순차 Trip 대기 중 위치나 경로 옵션이 달라져도 `CONTEXT_CHANGED`로 결과를 폐기하지 않는다.
이동 중 후보별 Trip의 출발 위치·시각은 달라질 수 있어 동일 출발점 비교를 보장하지 않는다. 검색 도중 출발 위치/옵션이 달라지면 해당 후보의 Trip 캐시는 제거한다.
검색 기준 위치와 현재 위치가 다르면 기존 결과의 이전 검색 기준 안내를 유지한다. 플랫폼 주행 제한과 경로 제출 시 목적지·경유지 변경 검사는 유지한다.

## 좌표 계약

- API 요청: NaviHelper 현재 위치 WGS84 → KATEC x/y (m).
- API 응답: KATEC `GIS_X_COOR`/`GIS_Y_COOR` → WGS84 위도/경도.
- Proj4J 1.4.3의 명시적인 CRS 파라미터를 사용한다. 경위도 좌표의 입력 축은 longitude/latitude이며 모델에는 latitude/longitude로
  저장한다.
- KATEC는
  `+proj=tmerc +lat_0=38 +lon_0=128 +k=0.9999 +x_0=400000 +y_0=600000 +ellps=bessel +towgs84=-115.80,474.99,674.11,1.16,-2.31,-1.63,6.43 +units=m +no_defs`
  로 정의한다. EPSG:5179나 WGS84를 그대로 대입하지 않는다.
- 투영/변환 파라미터는 [KOTI-KATEC 공개 정의](https://dacon.io/competitions/official/235682/talkboard/402145)를
  참고했다. 이 자료는 다른 데이터셋의 정정 공지이며 오피넷 전용 datum 보증은 아니다. **오피넷은 KATEC라고만 명시하므로 해당 datum 파라미터가 서비스와 정확히
  일치한다는 점은 남은 가정**이다. 독립 PROJ 기준값 대조는 구현 일치만 검증하며 서비스의 절대 위치 정확성을 입증하지 않는다.
- 한남동·분당·부산 기준값은 PROJ/pyproj로 별도 계산했고 JVM 테스트에서 투영 오차 5cm, 경위도 오차 0.000001도 이내를 확인한다.

## 좌표 전용 내비 연결

오피넷 UNI_ID는 앱의 주유소 ID다. 내비 POI ID로 전달하지 않는다. Trip에는 빈 ID/null sub-ID, 목적지·경유지 설정에는 빈 ID/빈 sub-ID를
사용한다. [좌표 PoC](poc/COORDINATE_ONLY_NAVI_POC.md)의 생성자 인자 계약을 따른다.

Trip은 순차 요청하고 이름에 요청별 UUID를 붙인다. 응답 목적지의 이름 토큰이 일치해야 해당 요청으로 수용하며, 좌표는 요청 위치에서 150m 이내의 도로 스냅만 허용한다.
토큰이 보존되지 않는 Navigation 버전은 타임아웃으로 실패한다. 기존 식별 POI fixture는 ID·실측 좌표의 엄격한 검증을 유지한다. 타임아웃/귀속 불명 시 공유
ledger의 불확실성 잠금을 유지한다.

Trip 캐시는 좌표·이름으로 구분하고 최초 출발 위치 50m 이내·동일 경로 옵션에서만 재사용한다. 새 검색은 가격을 다시 조회하며 위치/옵션 변경 시 새 토큰으로 Trip을
조회한다. 설정·완료 처리는 검색 시점의 가격과 조건을 사용한다.

목적지가 있고 기존 경유지가 없으면 좌표 전용 후보도 경유 추가를 제공한다. 기존 목적지를 유지하면서 `addWaypoint`로 첫 경유지를 추가한다.
SDK는 실제 추가 후에도 경유지 좌표를 `(0,0)`으로 반환할 수 있으므로 이 경우 좌표 검사만 생략한다. 좌표 전용 후보는 요청 이름과 빈 POI ID,
경유지 개수·순서, 기존 목적지 유지·경로 옵션·안내 상태를 확인한다. 0이 아닌 좌표는 기존 허용 오차로 검사한다.

빈 ID의 기존 목적지는 이름·좌표로 구분한다. 목적지 반영 성공은 이름·입력 좌표·경유 목록·옵션·안내 상태를 재조회해 확인한다.
결과 불명 시 자동 재제출하지 않는다.

경로 실패 후보는 가격·사유만 표시하며 비교·선택에서 제외한다. 기준 가격은 경로 확보 후보의 최고가다. 가격 기준시각은 주변 API에서 제공하지 않으므로 조회 시각과 구분한다.

## 검증과 한계

- `code`로 수정한 일반 API 실호출은 예시 좌표의 반경 3km에서 34건과 정상 가격·KATEC 좌표를 반환했다. 이전 빈 배열은 잘못된 인증 파라미터 `certkey`
  때문이었다. 해당 실제 후보 선택 전체 흐름은 별도 UI 검증이 필요하다.
- `CoordinateRepositoryIntegrationTest`는 `coordinateRepositoryProbe=true`일 때 변환한 한남동 좌표로 실제 저장소의
  Trip 2회·목적지 설정·원복을 확인한다. 원래 목적지/경유지가 있으면 변경하지 않는다. `coordinateWaypointProbe=true`로 좌표 경유 추가의 사전
  거부도 검사할 수 있다.
- 다른 내비 버전·실차에서의 이름 토큰 보존, 150m 스냅 허용 범위와 KATEC datum은 추가 확인이 필요하다.

## 점진적 결과

전체 유효 후보 (기존 최대 15곳 제한)에 sourceIndex와 로딩 상태를 부여한다. 첫 Pleos 성공부터 동일 세션을 관측하며 가격·조건·조회 시각은 고정한다.
READY는 편도 절약액/시간순, 동점 및 미확보 후보는 원본 순번을 사용한다. 로딩과 최종 경로 실패는 구분한다.
