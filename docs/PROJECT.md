# PROJECT.md

## 프로젝트 개요

**돌아갈 만큼 싼가? — 저렴한 주유소로 우회하는 것이 실제로 이득인지 계산한다.**

현재 경로 주변의 주유소 가격뿐 아니라 **주유소까지 우회하는 추가 거리·연료비·시간**을 함께 고려하여, 가까운 곳에서 주유할 때와 비교한 **예상 실질 절약액**을 안내하는 차량용 주유 의사결정 앱이다.

현대자동차그룹 차량용 앱 개발 공모전 프로젝트로, **Pleos Connect 차량 환경에서 사용하는 차량용 애플리케이션**을 개발한다. 일반 스마트폰 앱을 전제로 설계하지 않으며, 차량 내 화면과 조작 환경, 주행 안전 및 주행 규제를 고려한다. 차량 정보와 내비게이션 연동은 현대의 차량용 API 시스템인 Pleos SDK를 기준으로 검토한다.

- 상태: 로컬 mock 기반 Compose 프로토타입. 실제 차량·유가·경로·내비 연동은 개발 목표이며 구현 완료를 의미하지 않는다.
- 원안: 기존 추천 20번, 「Idea 6 돌아갈 만큼 싼가? — 주유소 실질 절약액 비교」
- 원안 작성일: 2026-11-05

## 현재 구현 및 모듈 구조

웹 참고 버전의 홈 → 주변 주유소 검색 → 목록·선택 상세 비교 → 경로 설정 완료 흐름을 Compose로 구현했다. 검색마다 3~8곳의 가상 주유소를 생성하며 모든
위치·가격·경로와 경로 설정은 mock이다. 정차 시연용이며, 차량 연료 정보는 startup에서 별도로 조회하지만 화면·계산에는 아직 연결하지 않는다. 백엔드는 호출하지 않는다.

| 모듈               | 역할                                                                                |
|--------------------|-------------------------------------------------------------------------------------|
| `app`              | Application의 Koin 조립, Navigation 3 백스택·팝업·화면 연결, Android 저장 경로 제공 |
| `core:design`      | 공통 테마·토큰·outlined 벡터 아이콘·버튼·탭·스위치·스텝퍼                           |
| `core:model`       | 순수 Kotlin/JVM 모델과 이동 방식별 비용·시간 계산                                   |
| `core:data`        | 저장소 계약, mock 검색·경로 설정, 메모리 비교 세션, Preferences DataStore           |
| `feature:main`     | 홈·결과·완료 화면과 각각의 ViewModel, 두 창 크기·두 테마 프리뷰                     |
| `feature:settings` | 주유 조건 팝업과 SettingsViewModel, 적용 전 초안 편집                               |

`core:design`은 로컬 Pleos 디자인 가이드의 색상·타이포그래피·그림자 토큰을 `JUYULOWTheme.colors`, `.typography`, `.shadows`로 제공한다. 기존 Material 컴포넌트는 매핑된 `MaterialTheme.colorScheme`과 `.typography`를 사용한다. 출처·매핑·서체 및 원문 해석은 [DESIGN.md](DESIGN.md), 아이콘 제작·사용 지침은 [ICONOGRAPHY.md](ICONOGRAPHY.md)를 참고한다.

의존 방향은 `app → feature/core`, `feature → core`, `core:data → core:model`이다. core는 feature나 app에 의존하지
않으며 feature 간 직접 의존도 두지 않는다. 저장소 계약은 `core:data`에 두고, 추후 실제 데이터·SDK 구현으로 교체한다. 별도 domain 모듈은 추가하지
않았다.

앱은 `MainActivity → JUYULOWTheme → JuyulowApp` 순서로 실행한다. app의 ViewModel이 Navigation 3 백스택을 소유하고,
Home / Results (sessionId) / Completion (selectionId) / Settings entry를 연결한다. Settings는
DialogSceneStrategy로 홈 위에 표시한다. 각 entry의 ViewModel은 entry가 제거될 때 해제된다. 창 크기 변경에는 흐름을 유지하지만 프로세스 재생성
시 홈에서 시작한다. 설정만 앱 전용 파일의 Preferences DataStore에 영구 저장한다.

검색 세션은 검색 당시 목적지·기준 경로·주유 조건·주유소 목록의 불변 스냅샷이다. 메모리 저장소는 활성 검색 묶음 하나와 마지막 경로 설정 결과를 보관한다. 정렬·모드 전환에는
선택한 주유소를 유지하며 재검색 때 새 1위를 선택한다. mock 경로 설정은 홈 정보를 즉시 갱신하되 기존 비교는 이전 기준을 유지하고, 새 홈 검색부터 갱신된 경로를 사용한다.
주유 조건은 적용 시 저장하며 닫기·뒤로가기는 미적용 초안을 폐기한다.
설정 저장 중에는 닫기 버튼·시스템 뒤로가기·팝업 바깥 터치로 설정 entry를 제거하지 않는다. 저장 완료 후 자동으로 닫히며, 실패하면 초안을 유지하고 재시도하거나 닫을 수 있다.

가로 1700 × 1184dp와 분할 창 840 × 1184dp 모두 목록·상세를 동일 너비의 좌우 2열로 표시한다. 두 열은 독립 스크롤하며 경로 설정 버튼은 왼쪽 목록 아래에
고정한다. 시스템 테마·SansSerif를 유지한다. NaviHelper PoC
기록은 [실험 보고서](poc/POC_TRIP_REPORT.md), [구현 기록](poc/POC_TRIP_IMPLEMENTATION.md)에 보존한다.

의존성 버전은 `gradle/libs.versions.toml`에서 관리한다. Koin BOM과 Android/Compose 연동, Lifecycle, Coroutines를 사용한다. Koin은 constructor DSL로 등록하며, Koin annotation/KSP/컴파일러 플러그인은 추가하지 않는다.

화면 전환·설정 저장에는 아래 의존성을 사용한다. HTTP 클라이언트·실제 API 연동은 구현하지 않았다.

| 모듈 | 의존성 | 용도 |
| --- | --- | --- |
| `app` | Navigation 3 runtime/UI `1.2.1`, Lifecycle ViewModel Navigation 3 `2.11.0` | 앱 내부 화면 전환 및 화면별 ViewModel 수명 관리 |
| `app` | Material 3 Adaptive, Adaptive Layout, Adaptive Navigation 3 `1.3.0` | 창 크기에 따른 배치와 Navigation 3 연동 |
| `app` | Kotlin Serialization core `1.12.0` | 화면 경로 직렬화 |
| `core:data` | Preferences DataStore core `1.3.0` | 연비·주유량 등 소규모 설정 저장 |
| `core:data` | Retrofit 및 Kotlin Serialization converter `3.0.0`, Kotlin Serialization JSON `1.12.0` | 외부 HTTP API와 JSON 데이터 처리 |

Serialization 플러그인은 `app`과 `core:data`에 Kotlin과 같은 버전으로 적용한다. `core:data`는 순수 Kotlin/JVM 구조를 유지하기 위해 Android 의존성이 없는 `datastore-preferences-core`를 사용하며, 저장 경로 등 Android 환경 정보는 실제 저장소 구현 시 외부에서 제공한다.

`app`에는 로컬 SDK 가이드 기준으로 Pleos Vehicle `2.3.2`, NaviHelper `3.0.5`, FusedLocation `1.1.3` 의존성을 등록했다.
`settings.gradle.kts`의 Pleos Maven 저장소에서 `ai.pleos.playground` 그룹을 받는다. `app/navigation`에 NaviHelper
조회·Trip 응답·경로/경유지·내비 화면 요청 어댑터와 필요한 세 내비 권한을 추가했다. `app/location`에는 FusedLocation 지원 확인·위치 조회/구독·접근
차단 안내, `app/vehicle`에는 Vehicle Fuel의 누적/현재 연비·잔량 capability 조회·값 조회/구독 어댑터를 제공한다. 세 클라이언트는 Koin
factory로 제공하며 소유자가 명시적으로 초기화·해제한다. FUSED_LOCATION·CAR_ENERGY 권한을 선언하되 위치 런타임 권한 요청 UI는 아직 없다. 현재 화면은
mock 저장소를 사용한다. Application은 startup에 Vehicle Fuel 3항목과 AAOS 탱크 용량·잔여 연료량·유종을 1회 조회한다.
`VehicleInfoRepository.fields`는 실제 값 우선, 실패 시 항목별 DataStore 기본값, 기본값이 없으면 미설정으로 제공한다.
AAOS 런타임 에너지 권한은 첫 사용 가능한 화면에서 요청하며, 주행 규제 상태에서는 보류한다. 차량 값은 화면·검색 계산 및 기존 수동 설정을 변경하지 않는다.
계약과 사용
제약은 [NAVIHELPER.md](NAVIHELPER.md), [LOCATION_VEHICLE.md](LOCATION_VEHICLE.md)를 참조한다.

## 기획 배경과 해결할 문제

리터당 가격이 조금 싼 주유소를 찾더라도, 그곳까지 돌아가는 데 연료와 시간이 추가로 든다. 가격 정렬만으로는 이번 주유에서 실제로 절약되는 금액을 바로 판단하기 어렵다. 이 앱은 사용자가 **‘얼마나 싼가’보다 ‘지금 돌아갈 가치가 있는가’**를 판단하도록 돕는다.

## 주요 기능 및 차량 특화 요소

- **후보 주유소 비교:** 현재 이동 방향과 목적지를 고려해 주유소 후보를 선택한다.
- **실질 절약액 계산:** 동일한 주유량을 가정하고 가격 차이와 추가 주행 연료비를 함께 계산한다.
- **시간 비용 선택:** 이동 시간은 별도 표시한다. 시간 비용은 기본 제외하며 사용자가 켜면 시간당 12,000원의 가정으로 차감한다.
- **연비·주유량 설정:** 차량에서 연비 정보를 제공하지 않으면 사용자 기준 연비와 예상 주유량을 입력한다.
- **내비 연동:** 사용자가 선택한 주유소를 경유지로 설정한다.

## 주요 사용 시나리오

1. 사용자가 목적지로 이동하는 중 주유소 비교를 실행한다.
2. 앱은 현재 경로 기준 주유소 후보의 가격·예상 추가 이동거리·시간을 계산한다.
3. 사용자는 예상 주유량을 확인하고 결과를 비교한다.
4. ‘예상 절약액이 작아 가까운 곳 선택’ 또는 ‘절약액이 커서 우회 선택’ 중 하나를 결정한다.
5. 선택된 주유소를 차량 내비에 반영한다.

## 계산식 및 예시

| 항목             | 계산식                                                                   |
|------------------|--------------------------------------------------------------------------|
| 가격 차이 절감액 | (기준 주유소의 리터당 가격 − 후보 주유소의 리터당 가격) × 예상 주유량(L) |
| 우회 연료비 | 기준 경로 대비 추가 거리(km) ÷ 예상 연비(km/L) × 연료 단가(원/L) |
| 예상 순절약액    | 가격 차이 절감액 − 이동 연료비 − 통행료 − 선택적 시간 비용               |

프로토타입의 기준 가격은 같은 검색 묶음의 최고가이며 이동 연료 단가에도 같은 값을 사용한다. 목적지 경유는 경유 경로에서 기존 경로를 뺀 거리·시간, 주유소까지·왕복은 전체
거리·시간을 비용으로 반영한다. 왕복은 출발·복귀 경로가 각각 다르며 주유 시간은 한 번만 더한다. 통행료는 경유에서 추가 비용, 나머지 방식에서 전체 비용인 mock 값이다.
시간 비용을 켜면 비용 기준 주행 시간과 주유 시간을 합쳐 환산한다. 계산 중간값은 반올림하지 않고 표시할 때 원·분·km로 변환한다.

기본 조건은 40L·12km/L·주유 5분·시간 비용 제외다. 설정 범위는 10~100L (10L 단위), 1~30km/L (1 단위), 주유 1~20분 (1분 단위)다. 목적지가
있으면 경유·주유소까지·왕복, 없으면 주유소까지·왕복을 제공한다.

설명용 예시:

- 가격 차이 50원/L, 30L 주유 → 가격 차이 절감액 **1,500원**.
- 추가 거리 3km, 연비 10km/L, 연료 단가 3,400원/L → 우회 연료비 **1,020원**.
- 예상 순절약액: 1,500원 − 1,020원 = **480원**.

**예시 숫자는 실제 주유소 시세가 아니다.**

## SDK·외부 데이터와 MVP 개발 계획

- **Pleos 개발 문서:** [로컬 Pleos SDK 가이드 목차](../pleos_sdk_guide/README.md)를 진입점으로 사용한다. 앱 설계 원칙·디자인·주행 규제, 개발 환경 구성·테스트 가이드와 각 SDK의 Programming Guide·API Reference를 작업에 맞게 참조한다. SDK 연동 시 권한, 초기화·해제, API 호환성 및 가용성을 확인한다. 아래 연동은 개발 계획이며 현재 구현 완료를 의미하지 않는다.
- **Pleos/NaviHelper:** 현재 위치·목적지 확인, 사용자가 선택한 주유소를 경유지로 요청하는 기능을 연동한다.
- **외부 데이터:** 오피넷의 주유소 가격 정보를 사용하며, 정보 갱신 시각과 제공 범위를 함께 표시한다.
- **외부 경로 계산:** 지도 길찾기 API로 기준 경로와 주유소 경유 경로의 거리·시간 차이를 구한다. NaviHelper가 여러 임의 후보 경로의 모든 비교 계산을 직접 제공한다고 가정하지 않는다.
- **연비:** 차량에서 확인 가능한 범위가 제한되면 사용자 설정값을 사용한다.
- **초기 시연:** 동일 목적지에 대해 주유소 후보 2~3개를 비교하고, 추가거리·시간·순절약액이 다른 화면을 보여준 뒤 한 곳을 내비에 연동한다.

## 차별점·위험·검증 과제

- **차별점:** 현재 주행 경로에서의 예상 순이익을 비교해 주유 전 우회 의사결정을 돕는다.
- **정확성:** 연비, 실시간 교통, 실제 주유량, 유가 변동에 따라 결과가 달라지므로 추정치로 표시한다.
- **외부 의존성:** 오피넷 데이터 이용 조건과 경로 API 비용·쿼터·상업적 사용 가능 여부를 사전에 확인해야 한다.
- **기존 사례와의 관계:** 차계부와 자동차 비용 관리라는 넓은 분야가 인접하므로 ‘주유 전 우회 의사결정’이라는 차별점을 강조한다.
- **안전:** 주행 중 긴 목록 비교나 금액 입력을 요구하지 않도록 한다.
